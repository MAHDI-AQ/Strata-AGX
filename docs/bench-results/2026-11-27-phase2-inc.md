# Phase 2 items 3 & 4 — incremental suffix CRC / persistent LmBufs (rejected)

Date: 2026-11-27. Branch: `lever/p2inc-items34`, base `39aa6cea4` (Phase 1 promoted as `41b26de66`).
Verdict: **no robust win; both levers reverted.** The source tree is byte-identical to the base.

## Levers measured

- Item 3, `STRATA_INCREMENTAL_SUFFIX_CRC=1`: carry the streaming int32 CRC32 state across warm
  admissions and continue the slot's suffix-draft history with only the new tokens; cold, rewound or
  length-mismatched states replay in full.
- Item 4, `STRATA_PF_LM_PERSIST=1`: keep the layer-major `LmBufs` device reservation (including the
  VRAM residual rows) across warm prompts instead of `cudaFree`/`cudaMalloc` on every turn.

Both are strict opt-ins (exact `1`); with them unset the code path is unchanged. The settings register
and `docs/SETTINGS.md` entries were removed again with the source.

Analysis: baseline p50 spans 438–764 ms on burst65 and 539–798 ms on burst196; each lever lands
inside that spread. Item 3's lower burst196 p50 (563.81 ms) is beaten by an untouched baseline arm
(539.02 ms) and costs 9% burst196 turns/min. Item 4 is slower than every baseline on burst196.
The combined arm is throughput-neutral but not a latency win. No arm reached the falsifier
(`warm_p50 < 400 ms`). Run-to-run spread is wider than any lever effect, so the measurement does not
support shipping either change. This agrees with the earlier inspection that the warm admission reads
only `delta-1` tokens and its setup is ~20–41 ms: removing an O(prefix) scan cannot move a ~500 ms p50.
